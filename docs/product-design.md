# 来开博客 · 产品设计文档

> 版本：v0.1（MVP 已上线） · 更新日期：2026-08-29

## 一、产品定位

一个**个人技术博客**：记录技术探索与思考，内容以 Markdown 写作 + Git 管理的方式发布，面向公网读者开放。

**核心原则**：内容优先、简单可持续。博客最大的风险是烂尾，因此每个阶段的范围都要克制，宁可功能少而长期运转，不要功能多而放弃维护。

## 二、目标用户

- **作者（我）**：希望写作流程足够轻——写一个 Markdown 文件、commit、即发布；不被后台管理和运维牵扯精力。
- **读者**：能快速打开、舒服地读完一篇文章（含代码块），并可通过 RSS 持续订阅更新。

## 三、功能规划

### MVP（当前版本，已完成）

| 功能 | 说明 |
| --- | --- |
| 首页文章列表 | 按发布时间倒序，展示标题、日期、摘要 |
| 文章详情页 | Markdown 渲染 + Shiki 代码高亮，亮/暗色跟随系统 |
| 内容管理 | 文章即 `src/content/blog/` 下的 Markdown 文件，Git 提交即发布 |
| RSS 订阅 | `/rss.xml`，博客的灵魂功能 |
| 草稿机制 | frontmatter 中 `draft: true` 的文章不出现在任何发布渠道 |
| SEO 基础 | sitemap、语义化 HTML、meta 描述 |

### P1（近期计划：让博客"真正上线"）

- **部署上线**：代码托管到 GitHub，使用 Vercel 或 Netlify 自动构建发布；绑定正式域名（替换配置中的 `example.com`）。
- **评论系统**：接入 giscus（基于 GitHub Discussions），零运维成本。
- **标签/归档**：文章量到 10+ 篇后，加标签页和按年份的归档页。

### P2（远期，视需要再做）

- 站内搜索（文章量大后才有意义）
- 访问统计（接免费的第三方，如 Umami/不蒜子）
- 关于页、友链页
- 独立深色模式开关（当前已自动跟随系统）

## 四、明确不做（Non-goals）

- 自建评论系统、后台管理、在线编辑器 —— 写作走 Git，评论用 giscus
- 多用户 / 账号体系
- 动态服务端（保持纯静态，无数据库、无服务器运维）
- 阅读量点赞等社交化功能（P1/P2 均不考虑）

## 五、成功标准

MVP 阶段不追求量化指标，以"可持续"为准：

1. 发布一篇文章的全程（写作 → 上线）不超过 10 分钟；
2. 每月至少稳定更新一篇；
3. 站点构建时间 < 1 分钟，Lighthouse 性能分 ≥ 95。

## 六、技术方案（概述）

- **框架**：Astro（纯静态输出，默认零 JS）
- **内容**：Markdown + Content Collections（schema 校验）
- **样式**：原生 CSS（CSS 变量 + 深色模式媒体查询），不引入 UI 框架
- **部署**（P1）：GitHub + Vercel/Netlify，push 即发布
- **质量约定**：每次改动必须提交 commit；交付前 `npm test`（类型检查 + 构建）必须通过
